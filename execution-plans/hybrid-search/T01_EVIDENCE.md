## Explicit blockers and acceptance limits

1. **RESOLVED for the 1k workload: driver/GPU proof.** On 2026-10-24 the pinned CUDA 12.9.1 image requirement failed on driver 551.61 with exit 125 / `unsatisfied condition: cuda>=12.9`; only its predicate had been tested then. On 2026-10-25, operator-installed 617.42 cleared startup and the actual GPU profile passed twice as recorded above. Keep the old failure as dated history, not a current blocker. GPU success is not acceptance of an annual archive.
2. **OPEN for T03 WAL, not T01: worker SQLite.** The read-only 2026-10-25 Ubuntu worker command `python3 -c "import sqlite3; from scripts.milvus_probe import wal_is_fixed; print(sqlite3.sqlite_version, wal_is_fixed(sqlite3.sqlite_version))"` returned `3.46.1 False` (exit0). This fails the fixed-version gate (3.51.3+, fixed3.50.7/3.44.6 branches). It records T01 runtime evidence and blocks T03 WAL enablement until a fixed worker runtime is provisioned; it does not block review of the completed T01 feasibility proof. No archive/WAL database was created and no SQLite/Python package was changed.
3. **OPEN: host/archive and rebuild capacity.** The earlier measured Docker ~5.8 GiB is below the documented 8 GiB standalone minimum; GPU-run host available RAM reached 1.164 GiB. CPU/GPU 1k success is useful proof, not supported-host certification, 10k/annual-corpus capacity, weekly-refresh performance or a CPU-only product decision. Larger representative data and rebuild overlap, sustained swap/RAM/VRAM and disk capacity remain untested. T01 stays awaiting review, not accepted; no T02 starts automatically.
4. **Temporary host configuration is preserved.** Existing `.wslconfig` memory6GB/swap2GB was left as found. No independent evidence proves the earlier session's claimed prior config; deleting it or shutting down all WSL could affect unrelated work, so restoration is an explicit operator action. Task-owned containers are stopped without deleting volumes after verification.
